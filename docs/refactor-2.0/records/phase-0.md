## 4. ADR 结论

### ADR-01：分支与提交

- 每阶段一个分支，阶段内按 WP 切分可独立构建、可独立回滚的提交。
- 业务缺陷不混入 UI 重构分支；依赖锁文件与业务变更分开提交。
- 当前 P0 文档先在现有工作区完成，不擅自切分支或提交；后续阶段从已合入 P0 的 `main` 开始。

### ADR-03：字体

- UI 使用 Geist Sans，终端使用 Geist Mono，优先采用 Fontsource 并只引入必要字重。
- 中文使用显式系统回退栈；用户明确选择过的字体不强制覆盖。
- 预算：字体文件 ≤32、总字节 ≤800 KB、`@font-face` ≤16；超预算改用自托管 WOFF2 子集。

### ADR-04：组件库

- P1 先完成 `@` 别名、`cn()` 和一个最小组件 Demo，再按需引入 shadcn-vue。
- 不全量生成组件；只把实际使用的组件纳入 `components/ui`，避免样板文件污染仓库。
- 若依赖或 Tailwind v4 兼容验证失败，改用同 API 的本地组件，不阻塞后续阶段。

### ADR-05：设置迁移

- 新增可选 `uiSchema`，版本 2；迁移只影响外观、字体和语义着色，不触碰服务器、凭据、隧道与会话。
- 仅旧值完全等于旧默认时迁移到 Geist；任何显式定制都保留。
- 迁移前保存 UI2 专用备份；逻辑必须幂等，旧版本丢失版本字段后再次升级也不会重复破坏用户选择。

### ADR-07：信息架构

- 保持原信息架构：左侧导航仍为「导航 / 会话 / 标签页」三区段，不新增「概览」「传输」顶级入口；传输记录仍从工作区右侧面板进入。
- 标签栏固定在主工作区顶部；导航中的会话列表是当前标签的另一种排列，不是第二套导航。
- 无恢复会话时停留在工作区空态，有恢复会话时按确认结果恢复。
- Debug 仍走设置页分区；旧 `settings/debug` key 保留为跳转别名。

## 8. 偏差与说明

| 偏差 | 原因 | 影响 | 处理 |
|---|---|---|---|
| 无法归档 UI PNG | `captureWindowPNG` 在非 Windows 返回不支持；原生窗口截图权限现已授予，但当前会话截图接口不向应用目录写文件 | P0 文件化视觉门禁未通过 | Windows 采集，或后续补 macOS/Linux 截图后端与落盘链路 |
| 临时 SSH/SFTP 夹具的 SysInfo 指标不完整 | 夹具只实现 SSH shell、exec 和 SFTP 最小协议，不模拟真实 OS 指标 | 仅影响看板数值真实性，不影响连通性/布局验证 | 后续可换成本地容器 sshd 采集完整指标 |
| 验证脚本不同于文档示例 | 示例只取首个 CSS，且无字体匹配时受 `set -euo pipefail` 影响 | 统计可能失真或误失败 | 汇总所有 CSS/字体文件，并显式处理零字体 |
| 原门禁要求五态 9 key 全存在 | SFTP、命令面板、右键菜单为条件挂载，正常状态必然缺失 | 原标准不可满足 | 改为常驻 key 始终命中、条件 key 在对应状态命中 |

`found/visible` 使用 `1/0` 表示。五种状态的 `overlapCount` 分别为 0/0/0/0/1；命令面板的 1 个重叠标记为预期浮层。

| Servers | topbar/nav/statusbar `1/1`；terminal `1/0`；无非预期重叠 |
| Settings | topbar/nav/statusbar/settingsPage `1/1`；无非预期重叠 |
| Tunnels | topbar/nav/statusbar `1/1`；terminal `1/0`；无非预期重叠 |
| Workspace | topbar/nav/terminal/statusbar `1/1`；无非预期重叠 |
