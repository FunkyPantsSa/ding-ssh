# 阶段验收记录

本目录存放每个阶段的验收结果。**每个阶段结束时必须新增/更新一份 `phase-N.md`，否则该阶段视为未完成。**

## 文件命名

| 文件 | 内容 |
|---|---|
| `phase-0.md` | 基线与护栏：13 组快照、选择器契约、ADR、回滚演练 |
| `phase-1.md` | 设计系统基座：令牌、字体预算、组件层、迁移四场景 |
| `phase-2.md` | 应用外壳与终端工作区：布局、终端、标签、右栏、缩放 |
| `phase-3.md` | 业务页面与设置：六页回归、Go 契约同步 |
| `phase-4.md` | 交互/自动化/交付：12 项自动化、性能、三平台、发布 |
| `ui-regression.md` | P4 的 12 项自动化回归明细（可独立维护） |
| `token-map.md` | P1 的 83 个 CSS 变量映射（可选独立文件） |
| `selectors.md` | P0 的选择器契约（可选独立文件） |

## 记录要求

1. 使用 [`../08-验收矩阵.md`](../08-验收矩阵.md) §7 的模板。
2. 每条勾选必须有证据：命令输出、快照名、截图路径或提交 SHA。
3. 快照本体在 `logs/ui-snapshots/`（不入 Git）；需要长期保留的截图压缩后放 `records/phase-N/`。
4. 遗留问题必须写「级别 + 计划修复阶段」，不允许只写「已知问题」。
5. 阶段记录随阶段分支一起合入 `main`，是发布说明的输入。

## 快速开始

```bash
cp docs/refactor-2.0/records/_模板.md docs/refactor-2.0/records/phase-0.md
```

然后把模板中的 `N` 替换为阶段号，按门禁逐项填写。
