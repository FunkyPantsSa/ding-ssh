# 05 · 阶段 4：交互、自动化与交付

> 优先级：P1　估时：8–10 人日　前置：阶段 3 门禁通过（6 个页面与设置拆分完成）
> 出口：命令面板/快捷键/状态反馈/动效统一；DOM 稳定标识与自动化回归通过；三平台基础检查通过；可发布
> 本阶段不新增业务功能，只做「操作方式、可观测性、质量与交付」。

---

## 1. 阶段目标

1. 命令面板从「搜索框」升级为全局操作入口：分组、最近、服务器搜索、动作、导航。
2. 快捷键集中注册，避免与终端/输入法冲突，并在设置页可查。
3. 空态/加载/错误/骨架/Toast 统一，消灭「点了没反应」。
4. 动效收敛到规范时长，尊重 `prefers-reduced-motion`。
5. 所有关键 DOM 加稳定标识，`ui.layout`/`ui.assert` 改为 `data-ui` 优先，自动化回归有脚本化清单。
6. 性能与包体达标，三平台（Windows/macOS/Linux）基础检查通过。
7. 文档、CHANGELOG、发布说明与回滚预案就绪。

## 2. WP4.1 命令面板与快捷键（P4-01 ~ P4-03）

### P4-01 命令面板 UI 与排序

文件：`components/command/CommandPalette.vue`（P2 已组件化）、`components/command/CommandGroup.vue`、`CommandItem.vue`、`stores/command.ts`（最近记录）。

设计：

```text
┌──────────────────────────────────────────────┐
│ Search commands, servers, actions...         │
├──────────────────────────────────────────────┤
│ RECENT                                       │
│ > Connect to node-01                         │
│   Open Local Shell                           │
│ SERVERS                                      │
│   node-01       10.0.0.10                    │
│ ACTIONS                                      │
│   Create Tunnel / Open Transfers             │
│ NAVIGATION                                   │
│   Overview / Settings / Debug                │
└──────────────────────────────────────────────┘
```

规则：

- 数据源仍是 `buildCommands({sessions, servers, ui})`，**不新增第二份命令清单**。
- 分组映射：`section` 字段 → RECENT/SERVERS/ACTIONS/NAVIGATION；「服务器」组只显示 `connect-*`，最多 50 条 + 「还有 N 台，继续输入筛选」。
- 搜索：大小写不敏感；匹配标题、副标题（`user@host`）、命令 id；优先级 `最近使用 > 前缀匹配 > 包含匹配 > 服务器命中`。
- 最近使用：`localStorage['ding-ssh:command-recent']`，最多 10 个 id；执行成功才写入；提供「清除最近记录」。
- 键盘：↑↓ 循环、Enter 执行、Esc 关闭、Tab 不离开面板、`Ctrl/Cmd+K` 再按关闭。
- 空态：显示「无匹配命令」+ 建议（检查拼写 / 打开服务器管理）。
- 可访问性：`role="dialog"`、`aria-modal`、`aria-activedescendant`、选中项 `aria-selected`、输入框 `aria-label`。
- 性能：>200 条时输入防抖 80ms；列表只渲染前 60 条（分组内滚动）。

**验收**：输入 `nod` 命中服务器；`open` 命中导航；执行后最近记录更新；1000 台服务器下输入不卡顿（打点 <50ms/键）。

### P4-02 命令注册与 Go 规则

- 新增命令（若 P3 已确认）：`overview`、`transfers`、`debug`、`about`；id 一旦发布不得改名。
- `commands.ts` 的 `commandEffect` 为每个新命令登记 `cap:''`、`confirm:false`、`note`（只切换视图/打开页面）。
- `internal/debugsrv/appctl_register.go` 的 `appctlCommandRules` 同步登记；未登记会降级为 `config.write` + 两段式确认，属于**功能回归**。
- `app.commands` 返回的 `count`、顺序、截断（500）不变。
- 增加 Go 测试：新命令可被 `app.command` 执行；未知命令仍报错；规则表与 `commands.ts` 键集一致（可加一个前端导出 JSON 的快照测试，或在 Go 测试中手工列出）。

**验收**：MCP 调 `app.commands` 能看到新命令；`app.command {id:"overview"}` 返回 `{ok:true, view:"overview"}`；无「未登记命令」警告。

### P4-03 快捷键统一

新增 `composables/useHotkeys.ts` + `hotkeys.ts` 注册表（唯一事实）：

```ts
export interface Hotkey {
  id: string
  keys: string            // 'Mod+K' / 'Mod+1' / 'Mod+='
  scope: 'global' | 'workspace' | 'terminal'
  label: string
  run: () => void
}
```

| id | 键（mac / win-linux） | 作用域 | 行为 |
|---|---|---|---|
| `command-palette` | Cmd+K / Ctrl+K | global | 开关命令面板 |
| `close-overlay` | Esc | global | 关闭面板/抽屉/菜单 |
| `close-tab` | Cmd+W / Ctrl+W | workspace | 关闭当前标签 |
| `switch-tab-1..9` | Cmd/Ctrl+1..9 | global | 切换标签 |
| `font-inc/dec/reset` | Cmd/Ctrl+= / - / 0 | terminal | 终端字号（由 TerminalView 处理） |
| `toggle-sidebar` | Cmd/Ctrl+B | global | 侧栏折叠（可选） |
| `toggle-context` | Cmd/Ctrl+Shift+B | workspace | 右栏开关（可选） |

保护规则：

- `event.isComposing` 或输入法组合中不处理。
- 焦点在 `input/textarea/select/[contenteditable]` 时，除 `Mod+K`/`Esc` 外不拦截。
- 终端处于 alt buffer（vim/less）时，不拦截 `Mod+W` 以外的按键；`Mod+W` 仍关闭标签（与现状一致）。
- 冲突检测：注册表初始化时若同一 `keys+scope` 重复，开发态 `console.warn` 并只保留第一个。
- 设置页「快捷键」表由注册表生成，避免文档漂移。

## 3. WP4.2 状态与动效（P4-04 ~ P4-05）

### P4-04 空态 / 加载 / 错误 / Toast

| 状态 | 组件 | 规则 |
|---|---|---|
| 加载 | `Skeleton`（表格 5 行 / 卡片 3 块） | 首次加载用骨架；刷新用行内 spinner，不整页闪烁 |
| 空 | `EmptyState` | 必须有标题 + 说明 + 主操作；区分「无数据」与「无匹配」 |
| 错误 | `ErrorState` | 显示用户可读原因 + 重试 + 可展开技术详情；不泄露密码/token |
| 成功/失败 | `Toast` | 3s 自动消失；错误 6s；同一操作不叠加多条；可手动关闭 |
| 危险确认 | `ConfirmDialog` | 删除/停止隧道/关闭主密码等；明确对象与后果 |

- 统一 `useToast()`；`ToastProvider` 挂在 `App.vue` 根。
- 连接失败/重连失败仍用终端内状态面板，不弹 Toast 洪水。
- 传输失败：行内状态 + 一条可关闭 Toast（同一任务只一条）。

### P4-05 动效

| 交互 | 时长 | 实现 |
|---|---:|---|
| Hover | 100ms | `--duration-fast` |
| 按钮反馈 | 100ms | `:active` 背景变化 |
| Tooltip | 150ms | 延迟显示 |
| Dropdown | 120ms | 透明度 + 2px 位移 |
| Dialog | 150ms | 透明度 + 4px 位移 |
| Sidebar | 180ms | 宽度/位移 |

- 禁止：弹簧、持续发光、大面积渐变、超过 8px 的位移动画。
- `@media (prefers-reduced-motion: reduce)` 全局把 duration 置为 `0.01ms`，并禁用位移。
- 终端输出不受任何 UI 动画影响（不在 `.xterm` 祖先上加 transition/filter/transform）。
- 连接状态点可用 1.2s 呼吸动画，但 reduced-motion 下静态。

## 4. WP4.3 DOM 稳定标识与自动化（P4-06 ~ P4-08）

### P4-06 标识规范

| 属性 | 用途 | 示例 |
|---|---|---|
| `data-ui` | 关键区域（`ui.layout` 使用） | `data-ui="topbar"`、`data-ui="context-panel"` |
| `data-view` | 当前视图（根节点） | `data-view="overview"` |
| `data-section` | 设置分区/调试 tab | `data-section="appearance"` |
| `data-testid` | 具体操作/元素 | `data-testid="server-row-<id>"`、`data-testid="command-item-overview"` |
| `data-state` | 元素状态 | `data-state="connected"`、`data-state="loading"` |
| `data-tab-id` | 标签标识（比 index 稳定） | `data-tab-id="<clientId>"` |

必须覆盖的区域：

```text
app, topbar, sidebar, nav-item-<id>, main, workspace, tabbar, terminal,
context-panel, sftp, sysinfo, transfers-panel, statusbar, command-palette,
command-item-<id>, settings, settings-nav, settings-section-<key>, debug,
modal, menu-pop, toast, empty-state, error-state
```

- 动态列表项（服务器行、标签、传输任务）用业务 id，不用数组下标。
- 保留现有 `aria-label`（自动化与可访问性共用），例如命令面板 `aria-label="命令面板"`。
- 旧 class 保留：`.topbar`、`aside.nav`、`.tool`、`.terminal-bg`、`footer.status-bar`、`.set-nav`、`.menu-pop`、`.qconn`。

### P4-07 选择器切换与旧别名清理

1. `debug/ui.ts` 的 `LayoutKey` 增加 `fallback?: string`：

```ts
const LAYOUT_KEYS: LayoutKey[] = [
  {name: 'topbar', selector: '[data-ui="topbar"]', fallback: '.topbar'},
  ...
]
```

2. `layoutOp()` 先查 primary，`found:false` 时查 fallback，并在返回项加 `viaFallback: true`（便于发现遗漏）。
3. 全部命中 primary 后，删除 fallback、`aliases.css` 与 `legacy.css`：
   - `grep -rn "var(--ink-\|var(--mist-\|var(--signal-\|var(--copper-" src` 必须为 0（theme 除外）；
   - `grep -rn "btn-primary\|\.modal\b\|\.menu-pop" src` 只允许出现在组件兼容层，不允许出现在新代码；
   - 删除 `ToggleSwitch.vue`、`SplitDivider` 中未使用样式、`style.css` 的旧类。
4. 删除 `legacy.css` 前先确认 `grep -rn "btn-primary\|modal-root\|menu-pop\|set-nav\|qconn" src` 只剩新组件里的兼容 class；删除旧类/旧变量单独提交，跑完整快照 diff；**不允许与功能改动混在一起**。

- 新的 Geist 视觉与字体变化；

- 降级说明：旧版本可读新配置，但会丢失 `uiSchema`（再次升级会重跑幂等迁移，不会覆盖自定义）。

回滚：

- 代码：`git revert` 阶段合并提交（阶段边界清晰）。
- 配置：`localStorage['ding-ssh:ui2-migration-backup']` 可恢复迁移前外观；`settings.json` 发布前备份。
- 若仅视觉回退：保留新组件层，回滚 token 映射提交即可（P1-03/P1-04 独立提交）。
