> 优先级：P0　估时：14–17 人日　前置：阶段 1 门禁通过（令牌/字体/基础组件/迁移可用）
> 出口：三栏新壳稳定，SSH/重连/多标签/本机 Shell/SFTP 联动/复制粘贴全部通过；`App.vue` ≤180 行
> 本阶段**只改外壳与终端工作区**，不改 Servers/Tunnels/Settings 页面内部（P3）。

## 1. 阶段目标与风险

### 目标

1. 把 1024 行的 `App.vue` 拆成 `layouts/*` + `views/TerminalWorkspace.vue` + 3 个 composable，目标 ≤180 行。
2. 顶栏横跨全宽、导航在顶栏之下、状态栏横跨全宽；右栏为可隐藏的上下文面板。
3. 导航重构为 INFO 架构：WORKSPACE / SESSIONS / TOOLS / SYSTEM。
4. 标签栏重做为紧凑主区标签（32px），保留拖拽排序、状态点、快捷键。
5. 终端区加 28px 会话头、空态、连接态；**不改 xterm 内核与常驻挂载策略**。
6. 右侧面板统一为 SFTP / SysInfo / Transfers 三 Tab 的 `ContextPanel`。
7. 分屏降级为高级功能（默认无入口，能力与状态保留）。
8. 窄窗口（900×600 起）与 80%–150% 缩放全部可用。

### 最高风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **R6 终端重挂载** | 拆分时误把 `v-show` 改成 `v-if`，所有终端重建 → 连接中断、缓冲丢失 | 拆分前给 `TerminalView` 加 `onBeforeUnmount` 日志断言；拆分后检查 `sessions.tabs` 与 `__dingDebugRegistry` 数量不变 |
| **R7 网格/拖宽错位** | `.shell` 网格 + 绝对定位 `WidthResizer` + Teleport 浮层共享 `--nav-w` | 先改网格、跑 `ui.layout`，再改拖宽；`--nav-w/--context-w/--ui-zoom` 仍写在 `<html>` |
| **R3 终端缩放** | 布局祖先新增 `overflow/transform/filter` 会导致 WebGL 位图/坐标异常 | 终端祖先只允许 `overflow:hidden` 在 `.terminal-slot`，不得加 transform/filter/contain |
| **R11 状态栏 26px** | 80% 缩放下指标不可读 | 只保留 4 项指标；80% 快照验证；不达标回 28px 并记录 |

## 2. 目标结构与尺寸

```text
.app-shell (grid)
├─ AppTopBar        grid-area: topbar    48px, 跨全宽
├─ AppSidebar       grid-area: sidebar   220px / 折叠 56px
├─ <main>           grid-area: main      自适应
│  ├─ TerminalWorkspace（v-show view==='workspace'）
│  │  ├─ TabBar（32px）
│  │  ├─ TerminalSessionHeader（28px）
│  │  ├─ terminal slots（absolute / v-show 常驻）
│  │  └─ EmptyState / SplitView（高级）
│  ├─ ServersPage / TunnelsPage / SettingsPage（P3 接管，本阶段保持原组件）
├─ ContextPanel     grid-area: context   300px（可隐藏 0）
└─ AppStatusBar     grid-area: statusbar 26px, 跨全宽
```

```css
.app-shell {
  display: grid;
  grid-template-columns: var(--nav-w) minmax(0, 1fr) var(--context-w);
  grid-template-rows: var(--topbar-h) minmax(0, 1fr) var(--status-h);
  grid-template-areas:
    "topbar  topbar  topbar"
    "sidebar main    context"
    "status  status  status";
  height: 100%;
}
.app-shell.no-context  { --context-w: 0px; }
.app-shell > .topbar   { grid-area: topbar; }
.app-shell > .nav      { grid-area: sidebar; }
.app-shell > .app-main { grid-area: main; min-width: 0; }
.app-shell > .tool     { grid-area: context; min-width: 0; }
.app-shell > .status-bar { grid-area: status; }
```

> **第三列的收起**：非工作区、或没有活动 SSH 会话、或用户关闭右栏时，给 `.app-shell` 加 `no-context`（把 `--context-w` 置 0），避免主区右侧留 300px 空白。不要用 `visibility:hidden` 隐藏列。
>
> **折叠态不要用 `.app-shell.nav-collapsed` 覆盖 `--nav-w`**：`<html>` 上的 `--nav-w` 还要供 Teleport 到 body 的浮层定位。折叠时由 `useLayoutWidths` 把 `<html>` 的 `--nav-w` 写成 56px（沿用现状逻辑），网格自然跟随；`.nav-collapsed` 只用于图标态样式。同理，右栏隐藏时把 `--context-w` 写成 0，且不依赖 Teleport。
>
> `WidthResizer` 的 `top` 必须从 `0` 改为 `var(--topbar-h)`，`inset` 仍按 `calc(var(--nav-w) - 4px)`；右侧同理。浮层（QuickConnect/modal）仍 Teleport 到 body，继续依赖 `<html>` 上的 `--ui-zoom` 与 `--nav-w`。
