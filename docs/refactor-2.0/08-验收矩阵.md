# 08 · 验收矩阵

> 本文是每个阶段的「出口检查表」。所有勾选必须有证据：命令输出、快照名、截图或记录链接。
> **没有证据的勾选视为未完成。**

---

## 1. 验收原则

1. **可回归优先于好看**：视觉改动必须能用 `ui.snapshot` / `ui.diff` 复现；功能改动必须有操作路径。
2. **数据不造假**：没有数据来源的指标、没有实际效果的开关，一律不验收通过。
3. **自动化不退化**：25 个 `ui.*` 工具、`ui.layout` 9 个 key、`ui.navigate`、`app.commands` 必须可用。
4. **终端零回归是红线**：WebGL/缩放/IME/回滚/复制粘贴任一失败，阶段不得通过。
5. **缺陷分级**：S0（终端不可用/数据丢失）、S1（核心功能不可用）、S2（明显视觉/交互问题）、S3（细节）。S0/S1 必须修完才能过门禁；S2 允许带已知问题但要有记录与修复阶段。

### 3.1 视觉 diff 判定

| 差异类型 | 允许 | 处理 |
|---|---|---|
| 颜色整体变化（token 替换） | 是 | 记录色值映射 |
| 字体变化导致行宽变化 | 是 | 确认无截断 |
| 圆角 10→8 / 14→12 | 是 | 目检按钮/弹窗 |
| 布局位移 >2px | 否（除非任务明确） | 查 grid/padding |
| 文字截断/换行变化 | 否 | 调整宽度或字号 |
| 终端尺寸变化 | 否 | 查右栏/导航宽度 |
| 滚动条出现/消失 | 否 | 查 overflow |

### 6.1 `ui.assert` 示例

```text
# ui.assert 一次只断言一个 selector；可用的检查字段：
# exists / visible / text / textContains / rectWithin / styles
ui.assert {selector:"[data-ui=topbar]", visible:true, styles:{height:"48px"}}
ui.assert {selector:"[data-ui=statusbar]", visible:true, styles:{height:"26px"}}
ui.assert {selector:"[data-ui=terminal]", visible:true, rectWithin:{x:0,y:0,w:1440,h:900}}

# 数量类断言用 ui.query 的 total
ui.query {selector:"[data-testid=server-row]"}
```

> 语法以 `internal/debugsrv/ui.go` 的 `uiAssertChecks` 为准（支持的字段：`exists`、`visible`、`text`、`textContains`、`rectWithin`、`styles`）。先跑一条最小用例确认，再批量写。

## 9. 缺陷分级与退出标准

| 级别 | 定义 | 示例 | 门禁处理 |
|---|---|---|---|
| S0 | 终端不可用、数据丢失、无法启动 | 终端黑屏、SSH 配置丢失、迁移清空服务器 | **必须修复**，阶段不通过 |
| S1 | 核心功能不可用 | 无法连接、SFTP 不可用、隧道无法启停 | **必须修复**，阶段不通过 |
| S2 | 明显视觉/交互问题 | 布局错位、文字截断、按钮无反馈 | 允许带问题过门禁，但必须有记录与修复阶段 |
| S3 | 细节 | 1px 偏差、文案不统一 | 可延后，记录即可 |

**退出标准**：S0/S1 = 0；S2 有明确 owner 与修复阶段；S3 记录在案。
