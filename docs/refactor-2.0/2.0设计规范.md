# ding-ssh UI 2.0 — UI 设计规范与改造方案

> 实施拆分、验收矩阵与阶段记录见 [`docs/refactor-2.0/`](./refactor-2.0/README.md)。

> 文档版本：v1.0  
> 项目：ding-ssh  
> 设计方向：Vercel Geist Developer Workbench  
> 适用技术：Wails v2 + Vue 3 + Pinia + Tailwind CSS v4 + xterm.js 6  
> 设计原则：Developer First / Dark First / Terminal First  
> 本文为 AI 辅助整理的设计方案，以现有仓库能力为基础制定。

# 1. 产品设计目标

## 1.1 产品定位

将 ding-ssh 定义为：

**面向开发者与运维工程师的本地优先 SSH 工作台。**

它不应该只是一个 SSH 连接工具，而应该是一个围绕远程终端构建的综合工作环境。

主要工作流程：

1. 管理服务器和连接配置。
2. 快速连接远程服务器。
3. 在多个终端会话间切换。
4. 在终端上下文中进行文件管理。
5. 管理 SSH 隧道和本地 Shell。
6. 查看远程机器状态。
7. 通过快捷键和命令面板完成高频操作。
8. 为自动化和 AI 控制提供可观察的操作界面。

## 1.2 核心设计原则

| 原则 | 具体要求 |
|---|---|
| Terminal First | 终端是整个应用的核心，而不是普通页面中的一个组件 |
| Dark First | 深色作为默认主题，优先保证长时间工作体验 |
| Information Density | 提高有效信息密度，避免大面积无意义留白 |
| Minimal Decoration | 少用渐变、阴影、玻璃效果和装饰性图形 |
| Keyboard First | 高频操作优先支持键盘 |
| Contextual UI | 工具面板围绕当前服务器和终端会话展开 |
| Progressive Disclosure | 高级配置按需展示，不在默认界面堆积 |
| Consistency | 全局统一颜色、字体、圆角、间距和交互状态 |

## 1.3 不做什么

本次 UI 改造不以以下内容为目标：

- 不做移动端优先设计。
- 不做复杂的卡片式 Dashboard。
- 不做类似 IDE 的复杂多窗口布局。
- 不追求终端 ANSI 颜色的高度自定义。
- 不追求大量动画。
- 不把每个功能都包装成独立的大型页面。
- 不为了视觉效果改变 SSH、SFTP 和隧道的业务行为。

# 2. 整体视觉方向

## 2.1 设计体系

采用以下组合：

| 层级 | 采用方案 |
|---|---|
| 视觉规范 | Vercel Geist |
| 组件实现 | shadcn-vue |
| CSS | Tailwind CSS v4 |
| 字体 | Geist Sans + Geist Mono |
| 图标 | Lucide，优先统一使用简洁线性图标 |
| 终端 | xterm.js 原生渲染 |
| 可访问性 | WCAG 2.2 AA |
| 布局参考 | IBM Carbon UI Shell |

Geist 是视觉身份，shadcn-vue 是组件实现方案，Carbon 只借鉴布局和信息密度，不引入额外的 React 组件体系。

## 2.2 视觉关键词

- 深色
- 克制
- 简洁
- 专业
- 紧凑
- 清晰
- 工程化
- 低干扰

界面应该像一个成熟的开发者工具，而不是一个企业管理后台。

## 2.3 参考风格

建议参考以下产品的视觉语言：

- Vercel Dashboard
- Vercel Geist Design System
- Visual Studio Code
- Linear
- GitHub Desktop
- Warp Terminal

其中以 Geist 为主要视觉基准，不直接复制其他产品的整体布局。

# 3. 全局设计 Token

## 3.1 色彩系统

采用 Geist 风格的中性色体系。

默认深色模式：

| Token | 建议颜色 | 用途 |
|---|---|---|
| background | #09090B | 应用最底层背景 |
| surface-1 | #111113 | 主工作区 |
| surface-2 | #18181B | 卡片、面板 |
| surface-3 | #202024 | 悬停、次级容器 |
| surface-4 | #27272A | 弹出层、选中容器 |
| border-1 | #27272A | 默认边框 |
| border-2 | #3F3F46 | 强调边框 |
| border-focus | #3B82F6 | 焦点边框 |
| text-primary | #FAFAFA | 主要文字 |
| text-secondary | #A1A1AA | 次级文字 |
| text-muted | #71717A | 辅助信息 |
| accent | #3B82F6 | 品牌强调色 |
| success | #22C55E | 成功、在线 |
| warning | #F59E0B | 警告 |
| error | #EF4444 | 错误、危险 |
| info | #3B82F6 | 信息 |

以上为项目建议初始值，不宣称是 Geist 官方原始 Token。后续应通过 CSS Variables 统一维护。

### 色彩使用原则

1. 页面默认使用中性色。
2. 蓝色只用于主要操作、焦点和选中状态。
3. 绿色、橙色、红色用于真实状态，不作为装饰。
4. 不允许一个页面同时出现大量高饱和颜色。
5. 不使用大面积彩色渐变。
6. 状态不能只靠颜色表达，还必须有文字或图标。

## 3.2 字体系统

推荐：

| 类型 | 字体 |
|---|---|
| UI 字体 | Geist Sans |
| 终端字体 | Geist Mono |
| 中文 UI 回退 | Microsoft YaHei / PingFang SC |
| 中文终端回退 | Sarasa Mono SC / 系统等宽字体 |

CSS：

```css
:root {
  --font-sans: "Geist Sans",
    "Microsoft YaHei",
    sans-serif;

  --font-mono: "Geist Mono",
    "Sarasa Mono SC",
    "Cascadia Mono",
    monospace;
}
```

字号：

| 场景 | 字号 |
|---|---:|
| 页面标题 | 20px |
| 区块标题 | 14px |
| 正文 | 13px |
| 辅助信息 | 12px |
| 标签 | 11px |
| 终端 | 13px（默认） |
| 表格 | 12px |

终端字体大小继续支持 Ctrl+=、Ctrl+-、Ctrl+0。

### 字体资源优化

目标：

- 移除不必要的多套字体捆绑。
- 优先只保留 Geist Sans 和 Geist Mono。
- 中文字体优先使用系统字体回退。
- 不为每种字重重复捆绑大量资源。
- 优先采用 WOFF2。
- 检查字体子集与实际字符覆盖情况。

注意：字体文件最终数量取决于字体版本、语言子集和字重，不能简单保证只有两个物理文件。

## 3.3 圆角系统

| Token | 数值 | 使用场景 |
|---|---:|---|
| radius-sm | 4px | 小标签、状态指示 |
| radius-md | 6px | 按钮、输入框 |
| radius-lg | 8px | 菜单、面板 |
| radius-xl | 12px | 模态框、主要容器 |

避免大量使用 16px、20px、24px 的大圆角。

## 3.4 间距系统

统一使用 4px 基准。

| Token | 数值 |
|---|---:|
| space-1 | 4px |
| space-2 | 8px |
| space-3 | 12px |
| space-4 | 16px |
| space-5 | 20px |
| space-6 | 24px |
| space-8 | 32px |

主要原则：

- 导航紧凑。
- 工具栏紧凑。
- 表格行高控制在 36～40px。
- 表单间距适中。
- 不使用大量空白撑开内容。

# 4. 应用整体布局

## 4.1 新布局结构

建议保留三栏架构，但重新定义各区域的职责。

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部：应用标识   搜索 / Ctrl+K       连接状态  设置  用户菜单 │
├────────────┬──────────────────────────────┬──────────────────┤
│            │                              │                  │
│ 左侧导航   │       主工作区               │  上下文工具面板  │
│            │                              │                  │
│ 工作区     │  页面标题 / 工具栏           │  SFTP             │
│ 服务器     │                              │  SysInfo          │
│ 分组       │  Terminal / Server List      │  Transfers        │
│            │                              │  Session Info     │
│ 本机终端   │                              │                  │
│ 隧道       │                              │                  │
│            │                              │                  │
├────────────┴──────────────────────────────┴──────────────────┤
│ 底部状态栏：当前会话 · 连接状态 · 运行时间 · 传输状态         │
└──────────────────────────────────────────────────────────────┘
```

## 4.2 区域尺寸

| 区域 | 建议尺寸 | 说明 |
|---|---|---|
| 左侧导航 | 220px | 可折叠，最小 180px |
| 主工作区 | 自适应 | 核心区域 |
| 右侧面板 | 300px | 可隐藏，最小 260px |
| 顶部栏 | 48px | 固定高度 |
| 底部状态栏 | 26px | 固定高度 |

窗口宽度不足时：

- 优先收起右侧工具面板。
- 左侧导航可以折叠为图标栏。
- 不要强制缩小终端字体。
- 不要在窄窗口中出现多个互相挤压的面板。

## 4.3 左侧导航

导航结构建议：

```text
DING-SSH

WORKSPACE
  Overview
  Servers
  Tunnels

SESSIONS
  Local Shell
  Active Sessions
    server-01
    server-02
    server-03

TOOLS
  Transfers
  Command History

SYSTEM
  Settings
  About
```

说明：

- Overview：工作台入口。
- Servers：服务器管理。
- Tunnels：端口转发管理。
- Local Shell：本机终端。
- Active Sessions：当前运行中的终端会话。
- Transfers：传输任务。
- Command History：命令历史。
- Settings：设置。

导航区段可以折叠，但不再提供复杂的六种排列组合。

服务器分组可以直接展示在 Servers 页面中，不需要在导航栏中无限展开。

# 5. 首页 Overview

## 5.1 设计目标

首页不是传统意义上的运营 Dashboard。

它的作用是：

- 快速连接服务器。
- 查看当前连接情况。
- 发现异常连接。
- 快速进入最近使用的会话。

## 5.2 页面结构

```text
Overview

[ Search servers...              ] [ Add Server ]

┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ Total Servers│ │ Online       │ │ Active       │
│ 32           │ │ 28           │ │ 4 Sessions   │
└──────────────┘ └──────────────┘ └──────────────┘

Recent Servers

┌───────────────────────────────────────────────────────┐
│ Name       Host          Status      Last Connected   │
│ node-01    10.0.0.10     Online      2 min ago         │
│ node-02    10.0.0.11     Offline     1 hour ago        │
│ gpu-01     10.0.0.12     Online      5 min ago         │
└───────────────────────────────────────────────────────┘

Recent Sessions

┌───────────────────────────────────────────────────────┐
│ node-01 · root · SSH                         Active   │
│ gpu-01  · admin · SSH                        Active   │
└───────────────────────────────────────────────────────┘
```

首页只展示少量有价值的信息。

不要增加没有实际数据来源的 CPU、内存、磁盘统计图。

服务器总量、在线状态和活跃会话必须来自现有状态数据。

## 5.3 服务器列表

服务器列表是高频入口。

字段：

- 名称
- IP / Host
- 用户名
- 端口
- 分组
- 状态
- 最近连接时间
- 操作

操作：

- 连接
- 编辑
- 复制
- 测试连接
- 删除

交互要求：

- 双击连接。
- 右键打开操作菜单。
- 支持搜索。
- 支持分组过滤。
- 支持收藏。
- 支持拖拽改变分组（如果现有数据模型允许）。

在线状态测试保留现有五步连接诊断能力。

# 6. Terminal 工作区

## 6.1 核心原则

终端必须是应用中视觉权重最高的区域。

打开终端后，不应被 Dashboard、状态卡片或无关工具挤占空间。

默认采用单终端工作模式。

```text
┌────────────────────────────────────────────────────────────┐
│ node-01 / root                                      ● Ready │
├────────────────────────────────────────────────────────────┤
│ [node-01] [gpu-01] [local-shell]                  +         │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                                                            │
│                  xterm.js Terminal                         │
│                                                            │
│                                                            │
│                                                            │
├────────────────────────────────────────────────────────────┤
│ ● Connected    SSH    10.0.0.10:22    00:32:18             │
└────────────────────────────────────────────────────────────┘
```

## 6.2 标签栏

保留多标签功能。

每个标签展示：

- 服务器名称
- 必要时展示用户名
- 连接状态
- 关闭按钮

状态：

- 绿色：已连接。
- 黄色：重连中。
- 红色：连接失败。
- 灰色：已断开。

要求：

- 不展示过多信息。
- 不允许标签过高。
- 不使用复杂渐变背景。
- 当前标签使用明显但克制的选中状态。
- 支持 Ctrl+1～Ctrl+9 切换。
- 支持 Ctrl+W 关闭。

## 6.3 终端主体

终端区域尽可能保持纯净。

要求：

1. 使用 Geist Mono。
2. 默认字号 13px。
3. 默认 ANSI 16 色方案统一。
4. 保留原生 ANSI、256 色和 TrueColor 支持。
5. 保留 5000 行回滚能力。
6. 保留 WebGL 优先、Canvas 降级。
7. 保留中文输入法兼容。
8. 保留复制、粘贴和右键交互。
9. 保留断线重连不清屏。
10. 保留命令补全。

终端背景建议使用 #09090B。

终端不增加卡片式容器和多层边框。

## 6.4 分屏策略

建议将分屏从默认工作模式中移除。

原因：

- 多数 SSH 运维场景下，标签比复杂分屏更直接。
- 分屏会增加布局管理和终端尺寸同步复杂度。
- 会压缩实际终端显示面积。
- 增加拖拽、缩放和焦点管理成本。

处理方案：

- 默认不显示分屏入口。
- 保留原有布局计算模块，暂不删除。
- 将分屏作为高级功能。
- 后续根据真实使用反馈决定是否彻底移除。

不能因为隐藏分屏就破坏已有会话状态或自动化接口。

## 6.5 命令补全

补全能力保留，但必须降低视觉干扰。

设计要求：

- 仅在有候选时出现。
- 采用紧凑浮层。
- 不遮挡命令输入区域。
- 候选内容使用等宽字体。
- 当前选中候选使用轻量高亮。
- 支持 Tab、上下方向键和自定义导航热键。
- 保留 Trie + FZF 排序机制。

# 7. 右侧上下文工具面板

## 7.1 设计目标

右侧面板不是第二个主工作区。

它应该围绕当前终端会话提供辅助能力。

顶部采用 Tab 切换：

```text
┌──────────────────────────┐
│ SFTP  SysInfo  Transfers │
├──────────────────────────┤
│                          │
│                          │
│      当前工具内容        │
│                          │
│                          │
└──────────────────────────┘
```

默认隐藏，用户需要时打开。

## 7.2 SFTP

SFTP 是重要功能，应当重点优化。

设计结构：

```text
SFTP

/var/www/app

[ Upload ] [ New Folder ] [ Refresh ]

Name           Size       Modified
-------------------------------------
config/        --         10:30
logs/          --         09:20
app.yaml       2.1 KB     08:30
main.go        12 KB      Yesterday
```

功能：

- 路径输入与直接跳转。
- 文件列表。
- 文件夹进入。
- 上传。
- 下载。
- 拖拽上传。
- 多选。
- 删除。
- 重命名。
- 新建目录。
- 传输进度。
- 取消传输。

交互：

- 文件名左对齐。
- 文件大小右对齐。
- 修改时间使用辅助文字。
- 文件夹和文件使用统一图标。
- 危险操作二次确认。
- 传输任务显示在统一 Transfers 中。

### 目录联动

必须保留：

- Shell 执行 cd 后更新 SFTP 路径。
- SFTP 跳转后同步终端工作目录。
- 保留两个方向独立开关。
- 保留 OSC 7 优先、prompt 兜底机制。

目录联动属于产品核心差异化能力，不应因 UI 改造而弱化。

## 7.3 SysInfo

  Usage          35%

Memory
  Used           12.4 GB
  Total          32 GB

Disk
  /              68%
  /data          72%

  RX             2.4 GB

要求：

- 优先展示数字和文字。
- 使用简单进度条。
- 不引入复杂监控大屏。
- 不虚构未采集的数据。
- 保留现有空闲暂停采集机制。

## 7.4 Transfers

统一展示上传、下载任务。

字段：

- 文件名
- 方向
- 进度
- 已传输大小
- 总大小
- 速度
- 状态

状态：

- Waiting
- Running
- Completed
- Failed
- Cancelled

保留令牌桶限速、并发控制和任务取消能力。

# 9. Command Palette

这是本次 UI 改造中应该重点强化的功能。

快捷键：

- Windows / Linux：Ctrl+K
- macOS：Cmd+K
- Esc：关闭

设计：

```text
┌──────────────────────────────────────────────┐
│ Search commands, servers, actions...         │
├──────────────────────────────────────────────┤
│ RECENT                                       │
│                                              │
│ > Connect to node-01                         │
│   Open Local Shell                           │
│   Open Settings                              │
│                                              │
│ SERVERS                                      │
│   node-01       10.0.0.10                    │
│   gpu-01        10.0.0.12                    │
│                                              │
│ ACTIONS                                      │
│   Create Tunnel                              │
│   Open Transfers                             │
└──────────────────────────────────────────────┘
```

要求：

1. 支持搜索服务器。
2. 支持快速连接。
3. 支持打开页面。
4. 支持创建本机终端。
5. 支持执行常用操作。
6. 根据当前状态动态生成命令。
7. 最近操作参与排序。
8. 保留现有命令注册机制。

不要把命令面板做成普通搜索框。

它是整个应用的全局操作入口。

**最终目标：**

让 ding-ssh 从一个功能丰富、配置较多的 SSH 桌面工具，转变为一个视觉统一、操作高效、终端优先的现代开发者工作台。

设计不应该让用户感觉功能变少，而应该让用户更容易找到功能、更容易完成操作，并且在长时间使用时不会被界面干扰。
