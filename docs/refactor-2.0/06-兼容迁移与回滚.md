## 4. 字体与主题迁移

### 4.1 字体迁移矩阵

| 用户当前值 | 判定 | 迁移结果 |
|---|---|---|
| `uiFont: "Inter"` + 其余为旧默认 | 未自定义 | `Geist Sans` |
| `uiFont: "Sora"/"Manrope"/"Source Sans 3"` | 显式选择 | **保留原值**；若字体包已移除，回退到 `system` 并提示一次 |
| `uiFont: "system"` | 显式选择 | 保留 |
| `terminalFont: "IBM Plex Mono"` + 其余旧默认 | 未自定义 | `Geist Mono` |
| `terminalFont: "JetBrains Mono"/"Fira Code"/"Cascadia Code"/"Source Code Pro"` | 显式选择 | 保留；若移除字体包，回退 `system` 并提示 |
| `terminalFontSize` | 任意 | 保留（13 默认） |

**关键**：字体包移除后，`fontsource` 不再提供对应字体。为避免「设置里选了一个不存在的字体」，P3 的字体下拉只列出「Geist / System」；旧值仍可读，但显示为「已移除（回退 system）」，并在保存时写回 `system`。提示只出现一次（`localStorage['ding-ssh:font-fallback-notified']`）。

### 4.2 外观/主题迁移矩阵

| 字段/场景 | 旧值 | 新值 | 条件 |
|---|---|---|---|
| `appearance.mode` | `preset` | `preset` | 不变 |
| `appearance.presetId` | `signal` | `geist` | 仅当 `appearance`、`fonts`、`theme` 全部等于旧默认 |
| `appearance.presetId` | `copper/ocean/...` | 保留 | 显式选择 |
| `appearance.baseTone` | `auto` | 保留（= System） | 一律保留 |
| `appearance.primary` | `#3ec4b4` | 保留（custom 模式）或随 `geist` | custom 不覆盖 |
| `theme`（终端色板） | 旧默认（signal dark） | `geist` 深色板 | 仅未自定义 |
| `theme.bgImage/blurAmount/textShadow` | 任意 | 保留 | 一律保留 |
| `theme` 自定义 ANSI | 任意 | 保留 | 一律保留 |
| `terminalColorMode` | 无配置文件（新装） | `auto` | Go 默认值（保持原行为） |
| `terminalColorMode` | 旧文件缺字段 | `auto` | Go normalize 保持旧行为 |
| `terminalColorMode` | `auto`/`vivid`/`off` | 保留 | 显式值 |
| `uiScale` | 80–150 | 保留 | 一律 |
| `tabBarPlacement` | `side`/`top` | 保留字段，新 UI 忽略 | 不写回 |
| `navSectionOrder` | 任意排列 | 保留字段，新 UI 忽略 | 不写回 |
| `uiSchema` | 0/缺省 | 2 | 迁移后 |

### 4.3 迁移执行顺序

```text
1. security 解锁完成
2. settingsService.getSettings()  → 原始 Settings
3. normalize（现有逻辑，补默认值）
4. migrateUiSettings()
   ├─ (uiSchema >= 2) → 跳过
   ├─ 备份 appearance/theme/fonts/terminalColorMode → localStorage
   ├─ 判定 untouched → 替换为 Geist 默认
   ├─ 写 uiSchema = 2
   └─ 返回 migrated=true
5. settings.loaded = true（界面可用）
6. 若 migrated → settings.save() 一次（异步，不阻塞首屏）
7. App 应用主题；终端色板同步
```

失败处理：

- 备份写入失败：仍迁移，但 `console.warn` 并在设置页显示「迁移备份不可用」。
- 保存失败：内存仍用新值；下次启动 `uiSchema` 仍为 0，重跑（幂等）。
- 迁移中抛异常：捕获 → 保持原设置 + `uiSchema` 不写 + 错误进 `ui.console`，绝不阻塞启动。

## 8. 回滚与降级

### 8.1 代码回滚

| 场景 | 回滚单元 | 步骤 |
|---|---|---|
| 令牌/字体导致观感不可接受 | P1 的 token/font 提交 | revert 对应提交；`aliases.css` 仍在，旧样式恢复 |
| 新壳布局问题 | P2 的 layout 提交 | revert 到「新网格」之前；App.vue 仍是单体，可运行 |
| 页面拆分引入 bug | 单页拆分提交 | revert 该页；旧 `ServerList`/`SettingsPage` 仍在（拆分采用「新增 + 切换」而非原地重写） |
| 迁移逻辑错误 | P1-17 提交 | revert 迁移；`uiSchema` 不再写入；旧配置原样 |
| 命令面板/快捷键问题 | P4 对应提交 | revert；`buildCommands` 仍可用 |
| 整体回退 | 阶段合并提交（`--no-ff`） | 整段 revert，回到上一阶段可发布状态 |

### 8.2 配置回滚

```text
1. 关闭应用
2. 备份当前 settings.json
3. 若迁移前备份存在：localStorage['ding-ssh:ui2-migration-backup'] → 手动恢复 appearance/theme/fonts/terminalColorMode
4. 或将 settings.json 中 "uiSchema" 置 0，重启触发幂等迁移（不会覆盖自定义）
5. 恢复 settings.json 备份（发布前那份）
6. 启动验证：服务器/凭证/隧道/会话记录完好
```

**注意**：降级到旧版本时，旧前端不认识 `geist` 预设，会回落到旧默认（signal），并可能把终端色板同步为 signal。这是**已知降级副作用**；迁移备份可用于恢复。

### 8.3 迁移失败应急

| 症状 | 处理 |
|---|---|
| 启动后外观错乱 | 检查 `ui.tokens`；删除 localStorage 迁移备份外的临时键；`uiSchema` 置 0 重跑 |
| 字体全部回退 system | 字体包未加载/路径错误；检查 `@fontsource` 导入与构建产物 |
| 终端颜色异常 | 检查 `settings.theme` 是否被预设覆盖；`appearance.mode` 是否为 preset |
| 设置保存后丢失 | 检查 `save()` 是否包含新字段；检查 Go normalize 是否丢弃未知字段（不会） |
| 旧版本打不开配置 | 检查是否新增了必填字段（禁止）；确认 `uiSchema` 可选 |

## 9. 契约变更流程

任何以下改动，必须先提交「契约变更」小节并更新本文，再改代码：

1. 新增/重命名/删除 `data-ui`、`data-testid`、`data-section`；
2. 新增/重命名 view、section key、命令 id；
3. 删除 CSS 变量或类名；
4. 修改 `ui.layout` 的 key 名称或语义；
5. 修改 `ui.view` 返回字段；
6. 修改 `settings.json` 字段语义（不是追加）；
7. 修改分屏/终端/调试注册表的行为。

流程：

```text
提案（本文新增一行） → 影响面检查（前端/Go/测试/README/快照）
→ 先加别名/fallback → 改代码 → 跑 ui.layout + ui.assert + 快照
→ 记录到阶段验收单 → 下一个阶段才允许移除旧名
```
