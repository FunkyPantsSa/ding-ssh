| Debug | `debug` | `settings.debug` + `App` 调试绑定 + 审计/日志服务 | 无 | 无（只读展示） |
| Command History（可选） | `history` | `historyService.query`（需按服务器） | 无 | **需新增只读 API**（P3-23） |

> 设计规范 §5.2 要求「Total/Online/Active 必须来自现有状态数据」。本阶段明确口径：
> - **Total** = `servers.servers.length`
> - **Online** = 有 `testResults[nodeId].reachable === true` 的节点数 **或** 当前有 connected 标签的节点；界面注明「最近一次测试 / 当前会话」
> - **Active** = `sessions.tabs.filter(t => t.status === 'connected').length`
> - **最近连接时间** = 本地 `server-meta.lastConnectedAt`（打开标签时写入），没有则显示「—」
> - **收藏** = 本地 `server-meta.favorite`（不影响后端数据模型）

## 6. WP3.4 Transfers（P3-13 ~ P3-14）

### P3-13 传输数据提升（关键改造）

现状：进行中的传输列表是 `SftpPanel.vue` 的组件内 `ref`，面板卸载/未打开时收不到进度事件。独立页需要把「进行中」提升到 store。

方案：

1. `stores/transfers.ts` 增加：

```ts
interface ActiveTransfer {
  key: string            // sessionId:direction:name
  sessionId: string
  serverName: string
  direction: 'upload' | 'download'
  name: string
  transferred: number
  total: number
  speed: number
  status: 'waiting' | 'running' | 'completed' | 'failed' | 'cancelled'
  error?: string
  startedAt: number
}

state: {records: TransferRecord[], active: ActiveTransfer[]}
actions: {upsertActive, updateProgress, finishActive, cancelActive, clearFinished}
```

2. 事件订阅从 `SftpPanel` 移到 `services/transfer-tracker.ts`：在会话建立/恢复时按 `sessionId` 订阅 `onSftpTransfer`，会话关闭时取消；SftpPanel 只读 store 渲染。
3. 历史仍走 `TransferRecord` + localStorage（200 条），完成/失败/取消时写入。
4. 状态映射：`waiting`（排队/未开始）、`running`、`completed`、`failed`、`cancelled`；UI 文案用中文。
5. 取消：需要 `sessionId + direction + name`，从 active 项直接取；保留 `sftpCancelTransfer`。

**风险**：这是本阶段唯一「改变数据流」的任务，必须单独提交，并回归：
- 面板关闭后进度仍更新；
- 切换标签不丢进度；
- 完成时历史只写一条（不重复）；
- 取消后状态为 cancelled，不写 completed。

### P3-14 Transfers 页面

文件：`views/TransfersPage.vue`、`components/transfers/TransferTable.vue`、`TransferStatusBadge.vue`、`TransferFilters.vue`。

- 顶部：进行中数量、历史筛选（全部/上传/下载/失败）、清空历史（确认）。
- 表格列：文件名、方向、服务器、进度（条+百分比）、已传/总大小、速度、状态、操作（取消/重试/打开本地目录/移除记录）。
- 进行中与历史同表，按状态排序（running > waiting > failed > completed）。
- 空态区分「没有传输任务」与「没有匹配记录」。
- 打开本地目录：沿用 `TransferHistoryPanel` 现有实现；失败时给路径与提示，不静默。
