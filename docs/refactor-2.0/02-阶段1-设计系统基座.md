# 02 · 阶段 1：设计系统基座

> 优先级：P0　估时：12–15 人日　前置：阶段 0 门禁通过（D1/D6/D7 已定稿）
> 出口：全局颜色/字体/圆角/间距/图标/基础组件全部走 token；字体资源下降 ≥80%；终端渲染零回归
> 本阶段**不改业务页面结构**（ServerList/SettingsPage/TunnelPage 的内部布局留给 P3），只换「地基」与「外壳可复用的基础元素」。

---

## 1. 阶段目标与非目标

### 目标

1. 把 `style.css` 里 117 处变量重组为 **primitive → semantic → component** 三层，并保留旧变量别名。
2. Tailwind v4 的 `@theme` 全部映射到语义 token，业务组件不再出现裸色值。
3. 字体从 9 族 / 293 文件收敛到 Geist Sans + Geist Mono，中文走系统回退。
4. 建立 `components/ui` 基础组件层（18 个），统一按钮/输入/弹层/表格/状态的可访问性。
5. 主题引擎 v2：支持 Dark/Light/System + Accent，新增 `geist` 预设，旧 7 套预设保留为高级项。
6. 终端 ANSI 16 色统一，明暗联动，语义着色默认关闭（仅新装）。
7. 一次性的设置迁移（`uiSchema`），幂等、可降级、迁移前备份。

### 非目标

- 不重排导航/顶栏/状态栏（P2）。
- 不改 Servers/Settings/Tunnels 的页面结构与交互（P3）。
- 不改 xterm 内核、WebGL 补丁、补全算法、Zmodem。
- 不做动效体系（P4）。

## 2. 目标文件结构（本阶段新增）

```text

│   ├── tokens.css          # primitive：色阶 / 间距 / 圆角 / 字号 / 动效
│   ├── semantic.css        # semantic：[data-tone=dark|light] 两套语义映射

│   ├── terminal.css        # 终端容器与 ANSI 相关变量（xterm 主题仍由 JS 注入）
│   ├── engine.ts           # v2：派生品牌色/强调色，保留 applyRootTheme API
│   ├── presets.ts          # + geist 预设（其余 7 套保留）
│   └── migrate.ts          # uiSchema 迁移与备份
```

`style.css` 最终目标 ≤ 200 行；其余按区块迁移到 `theme/*.css` 或组件内 `<style scoped>`（仅限布局微调，不允许裸色值）。

```css
  --color-primary-foreground: var(--primary-foreground);
  --color-success: var(--success);
  --color-warning: var(--warning);

  --font-mono: var(--font-mono);
```

关键点：

- 用 `@theme inline` 而不是 `@theme`：前者让工具类输出 `var(--color-x)`，才能在运行时切换主题；后者会在构建期固化。
- 旧 Tailwind 中性色兼容映射（`--color-slate-*` → 语义变量）保留到 P4，避免 300+ 处 `text-slate-*` 一次性全改。
- 类名规范：新代码使用 `bg-surface-1`、`text-muted-foreground`、`border-border`；**禁止** `bg-[#18181b]`、`text-[var(--mist-300)]` 这类写法（除终端/图表等特殊场景并注释原因）。

### P1-08 字体加载、子集与预算

1. 字体栈：

```css
:root {
  --font-sans: "Geist Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif;
```

2. 加载策略：Fontsource CSS 默认 `font-display: swap`；首屏不阻塞。若实测 CLS > 0.02，再考虑对 latin 子集加 `<link rel="preload">`（需要在 `index.html` 手写，Vite 会处理 hash 资源）。
3. 体积预算（P1 门禁）：

| 指标 | 基线 | 目标 |
|---|---:|---:|
| `@font-face` | 161 | ≤ 16 |
| 字体文件 | 293 | ≤ 32 |
| 字体总字节 | 未统计（先测） | ≤ 800 KB |
| CSS 体积 | 214 KB | ≤ 80 KB |

4. 终端字体：`TerminalView.vue` 的 `monoFontStack(settings.fonts.terminalFont)` 保持；新增 `Geist Mono` 选项并作为新装默认。**不得**把 `font-family` 写成 `!important` 覆盖 xterm 的测量逻辑。

### P1-09 字号与排版 token

| 场景 | 规范 | token | 使用位置 |

## 5. WP1.3 基础组件层（P1-10 ~ P1-14）

### P1-10 `@` 别名与 `cn()`

```ts
// vite.config.ts
import {fileURLToPath, URL} from 'node:url'
resolve: {alias: {'@': fileURLToPath(new URL('./src', import.meta.url))}}
```

```json
// tsconfig.json
"baseUrl": ".",
"paths": {"@/*": ["src/*"]}
```

```ts
// src/lib/utils.ts
import {clsx, type ClassValue} from 'clsx'
import {twMerge} from 'tailwind-merge'
export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

依赖：`npm i clsx tailwind-merge class-variance-authority`（shadcn 体系必需）。若走方案 B（自建），`clsx` + `tailwind-merge` 仍然建议保留。

若采用 shadcn-vue，还需要 `components.json`（`style: "new-york"`、`tailwind.css: "src/theme/tailwind.css"`、`aliases` 指向 `@/components` 与 `@/lib/utils`）；不要用 CLI 覆盖现有 `style.css`，只生成组件文件。

**验收**：`import {cn} from '@/lib/utils'` 在 `.vue` 与 `.ts` 中均可解析；`npm run build` 通过。

```ts
export interface ThemeVars {

  tone: 'dark' | 'light'
  accent: string
}

export function computeUiCssVars(appearance, fonts, tone): Record<string, string> {
  const accent = effectiveAccent(appearance)        // preset.primary 或 custom.primary
  return {

    '--primary-hover': lighten(accent, 0.18),
```

### P1-17 设置迁移（`theme/migrate.ts` + Go 模型）

**Go 侧改动（唯一允许的后端改动，且只追加字段）**

```go

type Settings struct {
    ...
    UISchema int `json:"uiSchema"` // 0/缺省 = 旧版；2 = Geist 2.0

// DefaultAppearance / DefaultFonts / DefaultTheme 改为 Geist 默认
// internal/store/settings.go: 文件不存在时返回 UISchema: 2
```

**前端迁移**

```ts
export const UI_SCHEMA = 2

export function migrateUiSettings(input: Settings, tone: 'dark' | 'light'): {
  settings: Settings
  migrated: boolean
  backup?: string
} {
  if ((input.uiSchema ?? 0) >= UI_SCHEMA) return {settings: input, migrated: false}

  const untouched =
    sameAppearance(input.appearance, LEGACY_DEFAULT_APPEARANCE) &&
    sameFonts(input.fonts, LEGACY_DEFAULT_FONTS) &&
    sameTheme(input.theme, LEGACY_DEFAULT_THEME)

  const backup = JSON.stringify({
    appearance: input.appearance, theme: input.theme,
    fonts: input.fonts, terminalColorMode: input.terminalColorMode,
  })

  const next: Settings = {...input, uiSchema: UI_SCHEMA}
  if (untouched) {
    next.appearance = GEIST_DEFAULT_APPEARANCE
    next.fonts = GEIST_DEFAULT_FONTS
    next.theme = {...input.theme, ...presetPalette('geist', tone)}
  }
  // 语义着色：新装与旧配置缺字段都由 Go 默认值给出 auto（保持原行为），
  // 前端不在这里强行覆盖，避免把老用户显式/隐式选择改掉。

  return {settings: next, migrated: true, backup}
}
```

调用点：`stores/settings.ts` 的 `load()` 在 normalize 之后、赋值之前执行；迁移成功则 `save()` 一次，并把 `backup` 写入 `localStorage['ding-ssh:ui2-migration-backup']`。

**验收**：

- 全新配置（无 `settings.json`）→ `uiSchema:2`、Geist 默认、语义着色 `auto`（由 Go 默认值给出，保持原行为）。
- 旧默认配置（signal/auto/Inter/IBM Plex Mono/13/auto）→ 迁移为 Geist，备份存在。
- 自定义配置（改了任意字段）→ 只补 `uiSchema`，其余不动。
- 旧配置缺 `terminalColorMode` → Go normalize 回落 `auto`（保持旧行为），迁移不覆盖。
- 迁移执行两次结果一致。
- 删除 `uiSchema` 模拟降级后再升级 → 不重复覆盖自定义配置。
