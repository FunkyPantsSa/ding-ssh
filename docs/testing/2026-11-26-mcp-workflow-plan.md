# MCP 工作流改进方案与验收

目标：调用方可以完成预检、选择工具、建立会话、执行任务、判断结果、关闭会话，无需猜权限、扫描新增标签或使用 DOM 选择器处理语义操作。保留现有工具兼容性、目标范围限制及用户确认。

## 实施范围

1. 增加 app.preflight(tool,args)：无副作用检查能力依赖、目标范围、路径、确认要求和平台支持；实际执行复用同源规则。修正本机重连不应依赖远端凭据权限的问题。
2. 改善错误：稳定错误码、缺失能力、结果是否已知和下一步操作；不会把未知执行结果当成可直接重试。
3. 完善 sessions.connect/disconnect/reconnect：返回明确 sessionId/tabId，支持有界等待，报告当前状态；增加 sessions.close/closeStatus，返回精确标签的关闭或待用户确认状态。
4. 提供可选 operations/debug/full 工具目录，默认 full 保持兼容；tools.search 支持发现推荐入口、别名和工作流。stdio 与 HTTP 使用一致的配置。
5. 强化独立任务为常规命令入口：exec.start 可有界等待并携带输出；jobs.wait 可携带输出，保留异步任务 ID、幂等键和输出游标。本机执行显式披露 shell，并支持 Windows shell 与 cwd/env。
6. 就绪状态与环境信息可观测，调用方可区分后端、前端和会话状态。

## 验收方法

- 单元与集成测试覆盖权限拒绝、不执行的预检、受限客户端范围、重连目标、等待超时、幂等、输出及确认边界。
- 构建隔离 Windows 桌面实例，通过真正的 MCP initialize/tools/list/tools/call 验证完整工作流；不连接保存的外部服务器、不使用保存的凭据。
- 从调用端记录调用次数和残余阻碍，修复后复测。覆盖成功、非零退出、缺失目标、参数错误、权限预检、异步等待、中文、清理及目录 profile。
- 运行完整 Go 与前端测试、生产构建，记录环境限制与未覆盖范围。

## 实施与复测结果（2026-11-26）

已实现以上六项。权限预检与实际调用复用同一能力/范围检查；会话操作返回可继续使用的 ID 与状态；工具目录 profile 只控制发现范围，不会授予权限；任务启动和等待均可直接返回输出，并保留异步 ID、幂等与结果游标；Windows 本机执行以明确的 PowerShell/cmd shell 运行，并按字面传入 cwd 和环境变量。关闭遇到用户确认时会返回可继续查询的状态，并排队处理多个待确认关闭。

最终验收在隔离 Windows 桌面实例中经 MCP initialize、tools/list 与 tools/call 完成，`scripts/audit/mcp_workflow.py` 的 16 项全部通过：operations 目录与 HTTP/MCP 列表一致；`exec.start` 条件权限元数据一致；能发现隐藏的 `ui.query`，实际调用仍返回 `PERMISSION_DENIED`；预检、参数拒绝、成功/非零/异步命令、中文 cwd/env、连接/断开/重连和会话清理均符合预期。验收没有连接保存的服务器或读取保存的凭据。该隔离桌面进程已关闭。

此前另用官方 MCP SDK 1.32.2 经 HTTP 和 stdio 传输验收：两种传输均初始化成功、健康检查成功，返回 128 个工具和 2 个资源模板。

Windows Go 验收为 13 个包通过、651 项通过、16 项平台或环境相关跳过、0 失败；前端 84 个测试文件、394 项通过，类型检查和生产构建通过。Windows 正式入口也已成功构建。CI 中新增的 Windows 测试任务尚未在 GitHub Actions 运行。

仍未覆盖真实外部 SSH 服务器、系统级安装/卸载/升级交付，以及 Windows ACL 的 Unix 权限位等价验证；这些边界不影响本次本机 MCP 流程验收。
