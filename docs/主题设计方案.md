# ding-ssh 主题系统设计方案

> **实现状态（2026-11）**：配色引擎已改为 Material Color Utilities 的 HCT / Tonal Spot，
> 并落地六类语义区域、Theme Atmosphere、Surface Separation 与材质模式。
> 本文保留设计目标与交互说明；具体算法与 Token 以 [`theme-system.md`](./theme-system.md) 为准。
> 下文出现的 “OKLCH” 仅代表设计阶段设想，当前实现不再使用 OKLCH 作为核心生成算法。

设计参考：Arc Browser · 面向开发者工具 · 支持明暗模式 · 动态主题 · 毛玻璃效果

## 一、设计目标

为 [ding-ssh](https://github.com/FunkyPantsSa/ding-ssh?utm_source=chatgpt.com) 设计一套参考 Arc Browser 的动态主题系统。

核心理念是：用户只需要选择一种颜色，应用就能自动生成一套协调、统一、可读的完整主题。

不是传统的“选择主题包”，而是通过颜色、明暗和透明度三个维度，让用户自由调整应用的视觉风格。

### 1.1 核心功能

| 功能    | 设计要求                      |
| ----- | ------------------------- |
| 主题颜色  | 通过二维颜色面板选择主色调             |
| 预设色块  | 提供常用颜色，一键切换               |
| 导航栏   | 比主内容区更浅、更柔和，形成层次          |
| 明暗模式  | 支持浅色、深色、跟随系统              |
| 背景透明度 | 滑块调整背景透明程度                |
| 毛玻璃模糊 | 独立控制背景模糊强度                |
| 实时预览  | 调整参数时立即更新界面               |
| 主题持久化 | 保存用户配置，重启后恢复              |
| 终端适配  | 保证 SSH 终端的可读性和 ANSI 色彩准确性 |

### 1.2 视觉设计原则

参考 Arc 的颜色生成逻辑，但不直接照搬浏览器界面。

ding-ssh 应保留开发者工具的专业感：

- 低饱和度、大面积柔和色彩。
- 导航栏与主工作区使用同色系的不同明度。
- 使用细微边框、柔和阴影区分界面层次。
- 深色模式优先考虑终端长时间使用的舒适度。
- 不允许主题颜色破坏终端文字、代码和状态信息的可读性。

### 2.1 二维颜色选择器

颜色面板采用 HSV 或 OKLCH 色彩模型。

建议内部采用 OKLCH 生成主题，用户交互层保留直观的二维选色方式。

交互规则：

- 横向移动：调整颜色饱和度或色度。
- 纵向移动：调整颜色明度。
- 拖动选择点：实时生成整套主题。
- 切换预设色块：更新当前颜色面板。
- 支持直接输入 HEX 颜色值。

### 2.2 预设颜色

建议内置 9 种基础主题：

| 主题       | 基础色       |
| -------- | --------- |
| Neutral  | `#E8E4DF` |
| Rose     | `#F19BC0` |
| Lavender | `#9E709F` |
| Coral    | `#F15E6A` |
| Orange   | `#FF805C` |
| Yellow   | `#F4D258` |
| Mint     | `#35DBA4` |
| Sky      | `#71B5D2` |
| Slate    | `#64698C` |

预设颜色仅作为生成主题的种子色，不直接覆盖所有 UI 元素。

## 三、界面颜色层次

主题系统必须区分不同的界面区域，而不是简单地把所有背景设置为相同颜色。

颜色关系示意：浅色模式导航栏略深于内容区；深色模式导航栏略亮于内容区，以保持清晰分层。

### 3.1 推荐的背景层级

| 区域       | 浅色模式      | 深色模式      |
| -------- | --------- | --------- |
| Sidebar  | 主色调，略深    | 主色调，略亮    |
| Main     | 主色调，略浅    | 中性深色，轻微染色 |
| Toolbar  | 接近 Main   | 接近 Main   |
| Card     | 比 Main 更亮 | 比 Main 略亮 |
| Hover    | 主题色轻微叠加   | 主题色轻微叠加   |
| Selected | 明显的主题色高亮  | 明显的主题色高亮  |
| Border   | 低对比中性色    | 低对比浅色     |
| Terminal | 独立背景      | 独立背景      |

重要： 浅色模式中，导航栏可以略深于右侧；深色模式则建议导航栏略亮于右侧。这样在两种模式下都能获得符合 Arc 风格的视觉层次。

## 四、主题生成引擎

建议采用 Seed Color → Color Palette → Semantic Tokens → UI Components 四层架构。

Seed Color

用户选择的基础颜色

Color Engine

OKLCH 色彩转换 / 明度 / 色度 / 对比度

Semantic Tokens

Sidebar / Main / Surface / Text / Border / Accent

UI Components

导航栏 / 标签页 / SSH 终端 / 文件管理 / 设置

### 4.1 颜色生成规则

不要直接通过 RGB 加减生成背景颜色，推荐使用 OKLCH 调整明度与色度。

例如用户选择橙色 `#FF805C`：

- 浅色模式：背景向高明度、低色度方向调整。
- 深色模式：背景向低明度、低色度方向调整。
- 导航栏：在主背景基础上产生适当的明度差。
- 选中状态：使用更接近原始种子色的颜色。
- 文本：根据背景亮度生成中性前景色，而非直接使用种子色。

初始建议：

| 参数          | 浅色模式        | 深色模式        |
| ----------- | ----------- | ----------- |
| Main 明度 L   | 0.94–0.98   | 0.15–0.21   |
| Sidebar 明度差 | -0.03～-0.07 | +0.03～+0.06 |
| 背景色度 C      | 0.01–0.05   | 0.01–0.04   |
| 主题强调色       | 中等色度        | 中等色度        |
| 普通文本        | 深灰 / 近黑     | 浅灰 / 近白     |

以上为初始设计参数，最终以实际显示效果和对比度测试为准。

### 4.2 Semantic Tokens

建议至少提供以下语义变量：

```
/* 基础 */
--theme-accent;
--theme-accent-hover;
--theme-accent-foreground;

/* 背景 */
--theme-bg-main;
--theme-bg-sidebar;
--theme-bg-toolbar;
--theme-bg-surface;
--theme-bg-elevated;

/* 文字 */
--theme-text-primary;
--theme-text-secondary;
--theme-text-muted;

/* 交互 */
--theme-bg-hover;
--theme-bg-active;
--theme-border;
--theme-focus-ring;

/* 玻璃效果 */
--theme-glass-opacity;
--theme-glass-blur;
--theme-glass-tint;

/* 终端 */
--theme-terminal-bg;
--theme-terminal-fg;
--theme-terminal-cursor;
--theme-terminal-selection;
```

所有组件统一消费语义变量，不直接引用预设颜色。

这样后续修改主题算法时，不需要逐个修改 UI 组件。

## 五、背景透明度与毛玻璃系统

这是 Arc 风格的重要组成部分。

需要区分两个概念：

透明度（Opacity） 决定背景能够透出多少内容。

模糊度（Blur） 决定透出的背景内容有多模糊。

两者应该独立控制，而不是使用一个滑块同时修改。

### 5.1 推荐参数

| 参数           | 范围       | 默认值  |
| ------------ | -------- | ---- |
| 背景不透明度       | 40%–100% | 85%  |
| 背景模糊         | 0–60px   | 24px |
| Sidebar 色彩强度 | 0%–100%  | 65%  |
| 主内容区色彩强度     | 0%–100%  | 20%  |

### 5.2 玻璃效果规则

- 优先应用于侧边栏、顶部工具栏、浮层和设置弹窗。
- SSH 终端默认保持不透明，避免影响文字阅读。
- 当透明度为 100% 时，可以关闭不必要的背景模糊。
- 在不支持系统级透明窗口的平台上，降级为应用内部毛玻璃。
- 系统级透明窗口和应用内部透明效果必须分别处理。
- 在性能较弱的设备上，允许关闭模糊，仅保留颜色透明效果。

注意： CSS `backdrop-filter` 只能模糊窗口内部背后的内容。要透出桌面壁纸或其他应用窗口，还需要桌面窗口框架及操作系统支持透明窗口。

## 六、SSH 终端的特殊处理

ding-ssh 是 SSH 客户端，不是普通浏览器，因此终端主题必须独立设计。

建议将主题划分为两个系统：

| 系统                | 管理内容                      |
| ----------------- | ------------------------- |
| Application Theme | 导航栏、工具栏、设置、文件管理器、弹窗       |
| Terminal Theme    | 终端背景、前景文字、ANSI 16 色、光标、选区 |

默认情况下，终端主题跟随应用的明暗模式，但不强制跟随应用主色。

例如：

- 应用主题：浅橙色。
- 导航栏：柔和橙色。
- 主内容区：奶油白。
- SSH 终端：深灰色。
- 终端 ANSI 色彩：保持专业终端配色。

建议内置 `Default Dark`、`Default Light`、`Tokyo Night`、`Catppuccin`、`Dracula` 等终端主题。

同时提供“终端背景跟随应用主题”开关，默认关闭。

这样既能保留 Arc 的视觉风格，又不会因为用户选择黄色、粉色等浅色主题而破坏终端体验。

## 七、主题配置与持久化

建议使用单一的主题配置对象保存用户选择。

以下是建议的数据结构，而不是要求直接采用的实现代码。

```
{
  "version": 1,
  "theme": {
    "mode": "system",
    "seedColor": "#FF805C",
    "preset": "orange",
    "sidebarTintStrength": 0.65,
    "mainTintStrength": 0.2,
    "glass": {
      "enabled": true,
      "opacity": 0.85,
      "blur": 24
    },
    "terminal": {
      "followAppTheme": false,
      "colorScheme": "default-dark",
      "backgroundOpacity": 1
    }
  }
}
```

### 配置行为

- 调整颜色时实时预览。
- 用户确认后持久化。
- 取消编辑时恢复修改前的主题。
- 支持恢复默认主题。
- 系统明暗模式变化时自动重新计算主题。
- 配置格式带版本号，方便后续迁移。
- 不把主题设置写入 SSH 服务器配置。
- 多窗口之间同步主题变化，避免不同窗口显示不一致。

## 八、用户交互设计

建议将主题设置集成在 ding-ssh 的“设置 → 外观”页面，同时提供快捷入口。

主题编辑器建议采用 Arc 风格的浮层，而不是复杂的独立配置页面。

交互流程：

1. 用户打开主题编辑器。
2. 选择浅色、深色或跟随系统。
3. 点击预设色块或在二维面板中选择颜色。
4. 应用实时更新导航栏、主工作区和控件颜色。
5. 用户调整透明度和模糊度。
6. 用户点击“应用”，保存主题。

推荐提供以下体验：

- 颜色变化采用 120–200ms 的平滑过渡。
- 拖动颜色选择点时实时更新，不需要点击确认。
- 支持重置单项参数。
- 支持键盘操作和精确颜色输入。
- 拖动滑块时显示当前数值。
- 浮层位置优先靠近外观设置入口。
- 避免颜色更新导致终端重建、SSH 会话断开或界面布局抖动。

## 九、性能、可访问性与兼容性

主题系统需要满足以下约束：

| 项目     | 要求                          |
| ------ | --------------------------- |
| 颜色计算   | 在本地完成，不依赖网络                 |
| 实时拖动   | 合并高频更新，避免大量重复渲染             |
| 主题切换   | 不重建 SSH 会话或终端实例             |
| 文字对比度  | 普通文本尽量满足 WCAG AA 4.5:1      |
| 交互控件   | 保留清晰的焦点状态                   |
| 高对比度   | 支持关闭透明和模糊效果                 |
| 系统动画偏好 | 尊重 `prefers-reduced-motion` |
| 透明兼容性  | 不支持时自动回退为实色背景               |
| 配置异常   | 自动回退到内置默认主题                 |

对于 Electron、Tauri 或 WebView 等不同桌面技术，需要根据项目实际采用的技术栈选择透明窗口实现方式，不能仅依赖 CSS。

## 十、实施优先级

P0 — 主题基础能力

建立 Semantic Tokens、明暗模式、种子色生成算法、Sidebar/Main 分层和主题持久化。

P1 — Arc 风格主题编辑器

实现二维选色、预设色块、实时预览、透明度与模糊度滑块。

P2 — 终端主题适配

将应用主题与终端 ANSI 配色解耦，支持终端主题预设和可选联动。

P3 — 高级主题功能

主题导入导出、自定义预设、多窗口同步、性能优化与系统级透明窗口适配。

## 十一、交付与验收标准

后续交给开发大模型时，要求先检查 ding-ssh 当前实际使用的前端框架、样式系统、桌面窗口技术和终端组件，再确定具体代码改造位置。

最终应达到以下效果：

- 选择任意预设色或自定义颜色，导航栏和主内容区能够自动生成协调的配色。
- 浅色模式中导航栏略深于主内容区；深色模式中导航栏略亮于主内容区。
- 透明度与模糊度能够独立调整，且不会影响终端可读性。
- 主题切换无需刷新、无需重新连接 SSH。
- 系统明暗模式切换时，应用主题能够自动响应。
- 重启应用后，所有主题设置能够正确恢复。
- 不支持透明效果的平台仍能正常使用完整的颜色主题。
- 现有 SSH、SFTP、会话管理等功能不因主题系统改造而受到影响。

最终设计定位：Arc Browser 的自由配色体验 + Vercel Geist 的开发者工具视觉规范 + 独立可靠的 SSH 终端配色系统。

这套方案优先追求统一、柔和、可读、可扩展，而不是复杂的动态特效。

说明：本方案依据提供的 Arc 截图与需求制定。未能核实 ding-ssh 仓库的具体源码结构，因此没有假定其现有技术栈或文件路径。
